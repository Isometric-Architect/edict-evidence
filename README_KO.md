# CSV에서 ‘미입력’과 ‘빈 문자열’을 구별해 넘기기

**AI 보조로 작성한 작은 참조 예시이며, 범용 CSV 수리 제품이나 호환성 보증이 아닙니다. NOTICE.md와 LICENSES.md를 함께 확인하세요.**

## 무엇을 하는 자료인가
CSV 파일을 읽을 수 있다는 것과, 원래의 의미를 보존한다는 것은 다릅니다. 이 자료는 `None`과 빈 문자열 `""`을 구별해야 하는 개발자에게, 조건이 명확한 작은 합성 예시와 실제 확인 수준을 제공합니다.

제공된 표본에서는 Python 3.13.5의 표준 `csv` 읽기·쓰기 양쪽에 `QUOTE_NOTNULL` 규약을 적용하면 두 값을 구별했습니다. 일반 reader까지 같은 의미를 유지한다는 뜻은 아닙니다. Python 3.12 문서는 reader 버그와 3.13 수정을 별도로 안내합니다. 여기서 3.12를 실행한 것은 아닙니다.

## 직접 확인할 때
허용된 환경에서 `python example.py`를 실행하면 묶음의 `example.csv`와 `expected.json`만 읽고 결과를 출력합니다. 새 설치·외부 통신·서버·고객파일 업로드가 없습니다. 새 제품을 설치하는 라이브러리가 아니라 기존 표준 기능을 사용하는 작은 예시입니다.

출력의 첫 번째 value가 JSON null, 두 번째가 빈 문자열인지 볼 수 있습니다. 문자 그대로의 NA, __NULL__, 쉼표와 줄바꿈이 있는 한글도 고정 표본에 들어 있습니다. 사용자의 운영 데이터는 받지 않습니다.

## 적용하기 전에
원래 값의 구별이 남아 있고 송수신자가 같은 규약을 사용할 수 있어야 합니다. 받는 도구를 바꿀 수 없으면 그 수신조건을 먼저 확인하세요. 이미 같은 빈칸으로 저장돼 구별이 사라졌다면, 이 파일만으로 원래 값이 무엇이었는지 확정할 수 없습니다.

이 표본은 pandas·n8n·Excel·데이터베이스의 제품 검증이 아닙니다. 특히 pandas의 전처리와 reader 결측정책을 표준 csv 시험으로 대신 보증하지 않습니다. 실제 프로그램에는 해당 환경의 수신값 확인이 필요합니다.

Python 공식 문서와 기본 기능으로 충분하다면 그것을 쓰면 됩니다. TDDA Serial, Frictionless 등 기존 메타데이터 체계도 있습니다. 이 자료가 새 표준이나 더 나은 파서라는 주장은 하지 않습니다.

사람용 설명과 `evidence.json`은 같은 범위와 한계를 전달합니다. 사용 후 제보는 선택사항이며, 합성 예제의 환경과 결과만 최소한으로 공유하는 방향입니다. 고객자료·계정·경로·비공개 값이나 그 해시를 요구하지 않습니다. 자동 수집은 없습니다.
